# Trustworthy Backtest Framework — 信頼性重視のバックテスト・フレームワーク

**ただ一つの目的のために作られたバックテスト・フレームワークです——
「本当に信じられるバックテスト」を作ること。**

> リポジトリ: `backtest-framework` ／ クオンツ・リサーチのポートフォリオ作品
> （作者: [@oimosanAI](https://github.com/oimosanAI)）

クオンツ・リサーチで本当に重要な問いは「この戦略は派手か？」ではなく、
「**このバックテストは信じられるか？**」です。本プロジェクトは後者の問いだけを
中心に設計されています。同梱の戦略（移動平均クロス）はあえて平凡で、その周囲の
「検証の厳密さ」こそが主役です。

**一言で言えば：** バックテストがつく三つの典型的な嘘——*ルックアヘッド・バイアス*、
*ノイズを実力と取り違えること*、*過剰最適化*——のそれぞれに、専用のテスト付き防御を
用意しました。ルックアヘッドは**構造的に不可能**にし**存在しないことを証明**
（`assert_causal`）。優位性は*偶然*（並べ替え検定＋ブートストラップ）と*データ
スヌーピング*（多重検定補正）に照らして検証。*過剰最適化*は*ウォークフォワード分析*で
暴きます。成果物は戦略ではなく、その「検証」です。

## なぜこのプロジェクトか（クオンツ選考での意義）

破綻した「優秀な」バックテストの大半は、同じ病気で死にます——その時点では
入手できなかったはずの情報を、シミュレーションがこっそり使ってしまうのです。
雇用側が信用できるフレームワークとは、バックテストがつく典型的な嘘——とりわけ
ルックアヘッド・バイアス——を、注意深い「慣習」で避けるのではなく、
**構造的に不可能にし、さらにテストで「存在しないこと」を証明する**ものです。
本リポジトリは意図的に小さく、これらの保証のすべてが数分の通読で確認できる
ようになっています。

## 信じられるバックテストの三本柱

バックテストは三つの異なる仕方で嘘をつきます。各「柱」は、ひとつの嘘と、それに対する
専用のテスト付き防御を対応させます。**結果が信用できるのは、三本すべてを同時に
クリアしたときだけです。**

### 第一の柱 — ルックアヘッド・バイアス・*「その時点で入手不可能な情報を使っていないか？」*

**慣習ではなく「構造」で排除。** バー `t` の終値で決めたシグナルは、`t` までに入手
可能な情報だけを使います。`t` で**終わった**値動きで利益を得てはいけません——その
値動きが終わって初めてシグナルを知ったのですから。エンジンはこれを**たった一箇所**で
強制します：

```python
# src/backtest/engine.py
position = target_position.shift(EXECUTION_LAG).fillna(0.0)  # EXECUTION_LAG = 1
```

執行ラグが各戦略ではなく**エンジン**側にあるため、どれほど雑に書かれた戦略でも、
シグナルを生んだのと同じバーで約定することはできません。

**主張ではなく「証明」。** `assert_causal()` は、ある分割点より**後**の価格をすべて
改変し、分割点**以前**のシグナルが一切変わらないことを検証します。テストは両方向で
確認します——移動平均クロスでは**成功**し、故意に仕込んだ未来参照戦略
（`_PerfectForesight`）を**検出して失敗**させ、テスト自体が機能していることを示します。

> 「未来を変えても過去は決して変わってはならない」。変わるなら、その
> バックテストはフィクションです。

### 第二の柱 — 統計的有意性・*「その優位性は本物か、ただの偶然か？」*

有限のサンプルは、コイン投げの戦略にすら見栄えの良いシャープを与え得ます。
`src/backtest/significance.py` は、優位性が偶然と区別できるかを測ります。全関数が明示の
`seed` を取り、すべての p値・信頼区間が完全に再現可能です。

- **並べ替え検定**（`permutation_test`）はポジションを順序そのままのリターンに対して
  数千回シャッフルし、その都度スコアを再計算します。得られる p値は*偶然が実スコア
  以上を出す頻度*です。**防ぐ嘘：** たまたま当たっただけのノイズ戦略。
- **ブートストラップ信頼区間**（`bootstrap_statistic`）は実現リターンをリサンプリング
  してシャープに誠実な誤差棒を与えます（自己相関に対応する移動ブロック版も選択可）。
  **防ぐ嘘：** 不確実性を伴わない点推定——区間が 0 をまたげば、シャープが正だとすら
  言えません。
- **多重検定／データスヌーピング補正**（`bonferroni_adjust`, `sidak_adjust`、および
  並べ替え版リアリティ・チェック `best_strategy_permutation_test`）は、多数の戦略を試して
  最良を報告したことを補正します。リアリティ・チェックの帰無分布は、共通シャッフル下で
  全候補にわたる*最大*スコアなので、チェリーピッキングが帰無分布に織り込まれます。
  **防ぐ嘘：** 50 個のパラメータの中の最良を、単一の発見であるかのように見せること。

### 第三の柱 — 過剰最適化・*「判定に使うデータそのものに戦略を合わせ込んでいないか？」*

`src/backtest/walkforward.py` は、**インサンプル**窓でパラメータを選び、その選択を直後の
**アウトオブサンプル**窓——選択時に見ていないデータ——で評価することを繰り返します。
**アンカード**（拡大窓）と**ローリング**（固定窓）の両方式に対応。両者の成績差
（**劣化, degradation**）が過剰最適化そのものを直接計測します。重要なのは、パラメータ
選択がインサンプル区間にしか触れず、アウトオブサンプル区間が時間的に厳密に後ろにある
こと——だからエンジンのルックアヘッド保証が各窓の内側でも保たれ、**アウトオブサンプルの
情報が当てはめに漏れることは決してありません。** **防ぐ嘘：** 自分の解答用紙に合わせ込んだ
曲線。

## 補助的な厳密さ

### 取引コストとスリッページ

コストは第一級のパラメータ（`commission`, `slippage`）で、**売買回転（turnover）**
に対して課されます——フラットな状態からの初回エントリーも含みます。テストは
*向き*（コストは収益を減らす）と*正確な大きさ*の両方を検証します。

### 正直で検証可能な指標

すべての年率換算係数は、根拠をコメントに記した名前付き定数です（取引日 252 日、
ボラティリティは `sqrt(252)` でスケール、標本標準偏差は `ddof=1`）。各指標は、
手計算できるほど単純な系列に対してテストされています（50% のドローダウン、
2 年で 2 倍 → CAGR は `sqrt(2) − 1` など）。

### 正直なデモ

`notebooks/strategy_vs_benchmark_SPY.ipynb` は**実際の SPY データ**で戦略を実行し、
バイ＆ホールドと比較します。掲載サンプルでは戦略は**全指標で負け**、ノートブックは
それを率直に述べます。`notebooks/significance_and_walkforward.ipynb` は同じ戦略を三本柱
すべてに通し、*データ駆動の*結論を出力します——実 SPY では見かけの優位性は**統計的に
偶然と区別できません**。負けた結果を誠実に示すこと、それ自体がデモなのです。

## 使い方

```python
from src.backtest.data import load_prices
from src.backtest.engine import run_backtest, BacktestConfig, assert_causal
from src.backtest.strategies import MovingAverageCrossStrategy
from src.backtest import metrics

prices = load_prices("SPY", "2010-01-01", "2023-12-31")

strategy = MovingAverageCrossStrategy(fast_window=50, slow_window=200)

# P&L を信じる「前」に、ルックアヘッドが無いことを証明する。
assert_causal(strategy, prices)

config = BacktestConfig(commission=0.0005, slippage=0.0005)
result = run_backtest(prices, strategy, config)

print(metrics.summary(result.returns, risk_free_rate=0.02))
```

### 第二の柱 — 優位性は本物か、偶然か？

```python
from src.backtest.significance import permutation_test, bootstrap_statistic

bar_returns = prices.pct_change().fillna(0.0)

# 偶然が戦略のタイミング能力にどれだけ並ぶか？
perm = permutation_test(result.positions, bar_returns, n_permutations=3000, seed=0)
print(f"並べ替え p値: {perm.p_value:.4f}")  # p値が高い => 偶然と区別できない

# シャープへの誠実な誤差棒。
boot = bootstrap_statistic(result.returns, n_resamples=3000, seed=0)
print(f"シャープ 95% 区間: [{boot.lower:.2f}, {boot.upper:.2f}]")  # 0 をまたぐ => 主張不可
```

### 第三の柱 — 過剰最適化していないか？

```python
from src.backtest.walkforward import run_walkforward

grid = [
    MovingAverageCrossStrategy(fast, slow)
    for fast in (10, 20, 50)
    for slow in (100, 150, 200)
    if fast < slow
]

wf = run_walkforward(prices, grid, train_size=500, test_size=125, mode="anchored")
print(f"平均インサンプル・シャープ : {wf.mean_in_sample:.2f}")
print(f"平均アウトオブサンプル     : {wf.mean_out_of_sample:.2f}")
print(f"劣化（過剰最適化の度合い）  : {wf.degradation:.2f}")  # 正 => 過剰最適化
```

## テストの実行

```bash
pytest                # 全テスト
pytest -v             # 詳細表示
pytest tests/test_engine.py::TestNoLookAhead              # 第一の柱：ルックアヘッド証明
pytest tests/test_significance.py                         # 第二の柱：偶然 vs 優位性
pytest tests/test_walkforward.py                          # 第三の柱：過剰最適化の検出
```

有意性・ウォークフォワードのテストは**正解が分かっている合成データ**で検証します——
並べ替え検定はランダムなシグナルでは*優位性なし*、整合したシグナルでは*明確な優位性*を
検出しなければならず、ウォークフォワードは全アウトオブサンプル窓を構造的にインサンプル窓の
後ろに配置し、水増しされたインサンプル成績を検出しなければなりません。ネットワークに触れる
テストはありません。

## 限界（正直に明記）

本フレームワークは*シミュレーションの妥当性*に最適化しており、機能の網羅性を
狙っていません。以下は**あえて未対応**です：

- **生存者バイアス（Survivorship bias）。** 渡されたティッカーをそのまま
  バックテストします。*今日*存在する銘柄だけを与えれば、すでに「生存者」を
  選んでしまっています。本フレームワークは時点（point-in-time）ユニバースや
  上場廃止銘柄を含むデータを提供しません。
- **単一資産のみ。** エンジンは一度に一つの価格系列を扱います。クロスセクション
  のポートフォリオ構築、ポジションのネッティング、リスクモデルはありません。
- **終値→終値の約定。** 約定は 1 バーのラグで翌終値にモデル化されます。日中
  約定、部分約定、寄り/引けのギャップはモデル化していません。
- **コストは単純な線形モデル。** 手数料とスリッページは売買回転に比例します。
  マーケットインパクト、銘柄ごとのビッド・アスク・スプレッド、空売りの貸株
  コストはモデル化していません。
- **有意性検定は代表的サンプルを前提とします。** ブートストラップと並べ替え検定は
  *与えられたデータの内側*でのサンプリングやタイミングの偶然を定量化しますが、
  サンプルに一度も現れない相場局面までは補正できません。また i.i.d. ブートストラップは
  強い自己相関を持つリターンの不確実性を過小評価します（移動ブロック版を使用してください）。
  リアリティ・チェックの閉形式代替としての*デフレート・シャープ比*はまだ提供していません。
- **ウォークフォワードは与えられたグリッドから選択します。** 最適化は渡された候補戦略の
  探索であって連続的なオプティマイザではありません。計測される過剰最適化は*グリッド選択*の
  ものであり、一般的なケースではありますが唯一ではありません。

これらはバグではなく「限界」です。それを明記すること自体が、本プロジェクトを
貫く誠実さの一部です。
